# 聚合输出模块：Godot 前端与语音合成播放一体化

树莓娘的表现侧由**一个**聚合输出模块承担：Godot 图像前端（Live2D 形象、字幕、表情、动作）与语音合成（TTS 合成与实际播放）合并为一个 waycast 模块，capability.kind = "both"（既接收表现输出单元，又把前端交互作为输入帧送回 hub）。PPT 的显示与翻页也包含在这个聚合模块内，不设独立 PPT 模块。

## Status

Accepted

## Context

用户裁定：语音合成与 Godot 前端合并为"聚合输出模块，一体化"，而不是两个分开的输出模块；并且**不需要独立的 PPT 模块**——PPT 的展示与翻页逻辑并入聚合输出模块。原树莓娘架构中"TTS 合成与播放均在核心完成、声音从核心主机输出"的产品行为，在这个模块化结构下转译为：语音合成与播放由聚合输出模块承担，音频由该模块部署的机器播放。

waycast 的 wire 协议（ADR-0008）以 capability 声明模块身份，允许单个连接同时承载输入与输出（kind = both，单连接全双工收发所有帧类型）。聚合输出模块正是这一能力的用例：它向 hub 声明输出 schema（表现单元）+ 输入描述（前端交互），在一条连接上收发 output_unit / result / input 帧。

## Decision

- **一个聚合输出模块**：整合 TTS 语音合成与播放、Godot 前端（Live2D 形象、字幕、表情、动作）、PPT 显示与翻页、前端交互输入。模块名由实现轮确定（如 raspberrygirl-presenter）。
- **output 侧**：接收核心 Agent 派发的表现单元。单元 payload 采用 waycast 通用 JSON，speech 文本、subtitle 文本、表情标签、动作标签、PPT 翻页指令等作为该模块 schema 声明的字段。模块接收单元后按语义执行，并返回 result 帧（成功/失败/细节），结果进入下一轮 Invocation（ADR-0002）。
- **input 侧**：把需要 Agent 响应的事件作为 input 帧发回 hub——包括前端交互（用户点击、请求）、PPT 状态变化（翻页完成、当前页、进度）等。这些输入触发新 Invocation，Agent 据此决定下一步表达。
- **表现细节封装在模块内**：TTS 与字幕/口型的时间对齐（含无词级时间戳的字幕方案）、实际播放进度、播放/停止/替换等表现控制全部在模块内部完成，不通过 waycast 协议传递。waycast 只负责把表现单元派发过来。
- **PPT 不设独立模块**：PPT 显示、翻页执行、当前页/进度状态都在聚合模块内；"推进并讲解"由核心 Agent 依据模块发回的输入帧（当前页、进度、指令结果）持续 Invocation 驱动。
- **部署**：聚合输出模块可部署在 core 主机上（声音从该机器输出），也可按需部署到前端侧；具体部署与资源不属本轮范围。

## Consequences

- waycast 核心不改动：表现控制、同步、播放这些都是模块内部实现，hub 只做 unit 派发与 input 收集。
- 核心 Agent 的"表达"就是向聚合模块派发 JSON 单元；它不知道模块内部是 TTS 还是 Godot。
- 旧 frontend / sound / orchestrator 中的 TTS、字幕、形象逻辑只作参考，需要时在新模块内重写，不作为复用来源。
- 聚合模块作为独立仓库（或多个仓库）承载，具体仓库命名与内部结构见实现轮。
