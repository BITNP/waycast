# 话权与打断由核心 Agent 自行决定：不做独立话权控制器与 Turn Epoch

树莓娘系统不保留独立的话权控制器、Turn Epoch、明确停止/新回复替换等旧词与会话控制语义。所有输入（语音、IM、弹幕、前端交互）都作为最终输入触发一次 waycast Invocation；是否打断当前表达、如何衔接，完全由核心 Agent 在推理中自行决定，并通过向输出模块派发表现单元来表达。输入模块与输出模块只负责各自的输入与输出，不参与话权判断。

## Status

Accepted

## Context

旧树莓娘架构（根目录 architecture.md）定义了一整套会话控制语义：按 session_id 隔离对话、Turn / Turn Epoch 拒绝迟到结果、话权控制器结合 VAD/ASR 判断打断、明确停止 vs 新回复替换、partial 不进入推理等。用户裁定：这套语义**全部不保留**。waycast 本身没有这些概念——每次输入恰好触发一次 Invocation（ADR-0006），记忆是全局单线程（ADR-0005），也没有会话隔离。用户确认这就是期望：waycast 不大改，其他模块去适配 waycast。

## Decision

- **一切输入都是最终输入**：不存在 partial 与 final 之分。任何抵达 hub 的 input 帧都触发一次 Invocation。输入模块（如语音输入）在自身侧决定何时发送——例如按静音/停顿把一段语音变成一条输入，但模块不做"这是部分还是最终"的标记，也不参与话权判断。
- **话权与打断是 Agent 的推理决定**：核心 Agent 收到新输入后，自行判断当前是否有正在进行的表达、是否需要打断、如何衔接，并把结论编码为给聚合输出模块的表现单元（例如"停止当前语音""开始讲解新内容"）。这是普通的工具/输出单元流程，不新增 waycast 协议消息。
- **输入模块与输出模块不参与话权**：输入模块只负责采集与发送 input 帧；输出模块只负责接收与执行输出单元。任何"打断候选""话权确认"逻辑都不在模块侧实现（模块可以按自身物理能力处理音频替换等，但那属于模块内部表现，不是话权语义）。
- **不保留旧词**：Turn、Turn Epoch、话权控制器、明确停止、新回复替换、session 隔离这些旧架构术语不再作为系统概念；对应的旧代码只读，不作为新实现约束。
- **会话与记忆**：沿用 waycast 全局单线程记忆（ADR-0005），不新增 session 隔离。所有输入累积进同一条对话历史。

## Consequences

- waycast 核心零改动：话权、打断、衔接全走现有 input → Invocation → output_unit → result 流程。
- 表达的"打断"效果由聚合输出模块内部实现（如新语音就绪后替换当前播放），模块在收到新单元时可替换旧表现，但这属于模块自身行为。
- 全局单线程记忆意味着多来源输入共享同一对话上下文；这被明确接受为用户选择，不是缺陷。
- 该领域术语在 GLOSSARY.md 中标记为"不再使用"（deprecated），避免新旧语义混淆。
