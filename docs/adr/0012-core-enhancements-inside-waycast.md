# 核心增强（如 RAG）在 waycast 核心内实现，但不改对外契约

waycast 现有功能与对外契约（wire 协议、模块帧、背压、全局记忆、工具）保持固定；但"固定契约"不等于"冻结功能"。对智能体有意义、且不属于输入/输出模块能力的功能——例如知识检索（RAG）、记忆策略、提示词装配、Agent 角色与行为配置——直接在 waycast 核心内实现或配置，作为核心增强。

## Status

Accepted

## Context

在第二轮讨论中用户明确：waycast 的现有功能和契约保持固定，不意味着不能加入有利于树莓娘智能体的新功能；这类新功能（例如 RAG 检索）**只能在 waycast 中实现，而不能作为输入模块**。原因是：RAG 是 Agent 推理过程的一部分（模型调用前检索事实并注入上下文），它既不是"外部信号输入"，也不是"表现输出"，没有资格作为输入/输出模块；它是核心 Agent 的能力。

## Decision

- **契约固定 = 对外接口固定**：hub 的 /ws/modules 帧协议、模块 capability、背压、输出结果进入下一轮（ADR-0002）、全局记忆（ADR-0005）这些对外契约保持稳定，模块无需因核心增强而改变。
- **核心增强允许**：对 Agent 有意义且不属于输入/输出模块的能力，作为 waycast 核心的一部分实现——包括 RAG 知识检索、提示词装配与角色配置（如 waycast.prompt.txt 树莓娘角色）、记忆/上下文策略、内置工具（如 get_time 之外的业务工具，若对 Agent 有意义）等。
- **增强遵守既有契约**：新增核心能力不能破坏 wire 协议、模块帧语义、背压、记忆闭环或结构化输出。增强的实现与既有 ADR（0001-0008、0009-0011）保持一致。
- **判别标准**：一项能力若能用输入/输出模块表达，就应做成模块（保持 waycast 通用）；若不能，且它是 Agent 推理本身需要的，才作为核心增强。边界不清时以 ADR-0009 的"waycast 核心通用性"为准并与用户确认。

## Consequences

- RAG 等能力未来在 waycast 核心内演进，技术选型（如向量库）按需确定，不属本轮范围。
- 模块侧保持简单：模块不承担检索、记忆、提示词等核心职责。
- 增强经得起"为什么这不在模块里"的审视：因为它是 Agent 推理的一部分，不是模块接口。
